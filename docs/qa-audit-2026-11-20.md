# RUNVAX full-application audit (Playwright), 19–20 Nov 2026

Written for: the product owner deciding whether the build is worth continuing and what to do next.

## How this was tested
- Real Chromium (Playwright), desktop 1440×900 and Pixel 7 phone viewport.
- Local dev server on port 3200 against a **throwaway MySQL database** (`runvax_qa` on port 3399). Production was never touched.
- All email (platform and campaign) was redirected to a **local SMTP sink**, so nothing real was sent. `RESEND_API_KEY`, `GITHUB_TOKEN` and `APIFY_TOKEN` were blanked for the run.
- Real calls were made to Google Places (about 40 businesses, cached) and OpenAI (a few dozen calls, about $0.06 per the admin API-cost page). Snov, Apollo and Paystack were not exercised, and WhatsApp and Telegram were not connected.
- Everything was registered and driven through the UI like a customer: sign-up, verify, sign-in, trial, Find Prospects, campaigns, agents, Career Agent, admin.
- Test accounts were fictional (`@example.com`). Screenshots are in `docs/qa-audit-2026-11-20-shots/`.

## Verdict
**Worth continuing.** The three things you set out to do all work end to end: find businesses and decision-makers, run an outreach campaign, and have a Career Agent produce honest applications. Beyond that, an AI Agent Studio exists and works. The code is healthy (type-check clean, 1,688 of 1,690 tests pass).

It is **not yet a business**. There is no way to take money, a few outbound-quality defects would embarrass users, and the AI features depend on an OpenAI key that was out of credit in this environment. Those are fixable in days, not months.

## Problems, ranked

### P0: blocks launch or damages trust
1. **No way to get paid.** "Upgrade plan" shows "Soon", `/pricing` redirects home, and admin shows ₦0 revenue (the "1 paid / 1 payment" is the free trial). After the 10-day trial there is nothing to sell. Your preferred structure (Starter $9 / Professional $19 / Agency $49) is still unbuilt.
2. **OpenAI credit.** The key the dev server loaded returned `429 You have no credits remaining`. The campaign builder silently fell back to a rule-based planner, which produced subjects like "our product for {{business}}" and ignored the actual offer. A different key (in `.env`) worked. I did not read `.env.local`, so I don't know which key production uses. **Check the production key and billing first.** Also make the fallback loud, since the only hint was a small grey notice.
3. **Emails ship with a literal "[Your Name]".** The AI writes a placeholder signature, and the app sends it. The confirm dialog does not warn, and there is no check that Settings → Your Name is filled. All three test sends went out this way.
4. **Transactional emails are branded "Beam AI Team"** (verification, welcome, reset, trial). The product is RUNVAX. Check `APP_NAME` in production.

### P1: quality and trust
5. **Decision-maker accuracy.** Contact lookup returned a "Lead Legal Advisor", an "Operations and Communications Manager" and Dental Assistants for dental clinics, and rarely the owner or principal dentist. Role ranking needs work for the "reach the owner" promise. Also one lookup was still "Looking up the team…" after 100 s.
6. **First email is generic.** "Hello, I'm a web designer in Lagos…" has no business-specific hook and the same body for every lead. A "personalise with the RUNVAX pitch engine" step exists but is optional and separate. Make it the default for the first touch.
7. **Replies are not ingested automatically.** The Inbox only reads the mailbox when the user presses "Check my inbox", and no cron does it. This weakens the "AI workforce that engages" story. Also, IMAP is assumed on port 993.
8. **SMTP password is stored in plain text** in `UserSettings.smtpPass` (confirmed by reading it back). The integrations store already has `crypto.ts`; use it. The user-supplied SMTP host and port also allow probing internal addresses (SSRF), so restrict it.
9. **Public agent chat page** (`/chat/<key>`) is wrapped in RUNVAX app chrome (sidebar, "Log in", "Sign up free"). A clinic cannot show that to patients. It should be a clean, unbranded page.
10. **Career Agent job supply is thin for Nigeria.** Sources were Himalayas (global remote, postings about 18 days old, one employer filled the top 3) and Google Maps "open application" targets. Arbeitnow was skipped. There are no Nigerian boards (Jobberman, MyJobMag, and so on). Auto-submit covers only Greenhouse and Lever, so real-form yield will stay low.

### P2: polish
11. Legacy V1 pages (`/dashboard`, `/pipeline`, `/settings`, `/command-centre`) and every marketing page log a React **hydration error** (text mismatch from the `v2n-` style block). Signed-out visitors also trigger 401 calls to `/api/prospects`, `/api/user/*` on every public page.
12. Phone layout: Home scrolls horizontally by about 76 px, and Settings has about 22 overflowing elements.
13. Wizard position is not remembered: the Career setup restarts at step 1 on reload (data is kept).
14. Each AI build creates a draft campaign, so testing left 5 empty duplicates. Consider "save on Open campaign" only.
15. Receptionist agent cannot be tried until a booking-page link is entered, and the error appears only after sending a chat message. Validate earlier.
16. The test email has no `List-Unsubscribe` header and no Reply-To. Real sends do have the unsubscribe header, but Reply-To was empty in both.
17. Discover-by-industry uses a LinkedIn-style list with no "Dental" or similar niche categories (the page itself explains to use job titles).
18. The signed-out Find page shows only "Free plan" counters because the trial banner persists after signing in on some pages (visual only).
19. Admin counts trials as "Paid" and shows ₦0 "payments". Separate trials from revenue.

## Which goal is closest to working?
- **Freelancers getting clients (B2B acquisition):** about 80%. Discovery, enrichment, sequencing, sending, unsubscribe, CRM and appointments are all there. Gaps: sender-name placeholder, generic first emails, manual reply checking, decision-maker precision, and deliverability setup guidance for the user's own domain.
- **Career Agent getting clients/jobs:** about 70%. The profile, matching and honest application writing are excellent. Weak spots are job-source breadth for Nigeria and real submission yield.
- **AI Agent Studio:** about 85%. This is the most polished piece and arguably the most sellable to local businesses.

## Recommended next steps (in order)
1. Confirm the production OpenAI key and billing, and add a visible "AI is offline" banner when the fallback is used.
2. Fix the "[Your Name]" problem (block run until sender name is set, and stop the AI writing placeholders). Fix "Beam AI Team" branding.
3. Build the payment path (Paystack plans are already configured in env) and the pricing page, then separate trials from revenue in admin.
4. Make first-touch personalisation the default, and tighten decision-maker role ranking (owner, principal, managing director first).
5. Auto-check replies on a schedule (cron or IMAP IDLE), or poll while the Inbox is open.
6. Encrypt the SMTP password and restrict SMTP hosts.
7. Clean public chat page, then the hydration error, 401 noise and mobile overflow.
8. Career: add one or two Nigerian job sources.

## Test caveats
- Dev mode (`next dev`) is slower than production and caused cold-start hangs that were not real bugs.
- The mail sink accepts everything, so real deliverability (SPF/DKIM, spam placement) was not tested.
- Not exercised: Snov/Apollo/Hunter verification credits, WhatsApp, Telegram, Google OAuth, Calendly booking, WordPress, Paystack, cron jobs, and the gated `/acquisition` Industry Engine (it redirects to `/command-centre` when off).
- The `.env.local` file was deliberately not read.
